# CodexHp 동적 그래프 시간 구간 설계

## 목표

Usage Overlay의 토큰 그래프 영역에 수용 가능한 전체 시간 구간만큼 실제 토큰 사용 기록을 표시한다. Appearance 설정에는 현재 값으로 결정되는 표시 시간을 사용자가 바로 확인할 수 있는 영문 안내를 제공한다.

## 현재 문제

- 토큰 활동 수집은 15초 버킷 60개로 고정되어 최근 15분만 읽는다.
- 기본 그래프 영역은 폭 178px이고 막대 슬롯은 2px이므로 89개 버킷, 즉 22분 15초를 수용한다.
- 이 차이로 그래프 왼쪽 약 7분 15초 구간이 실제 데이터 없이 남는다.
- Overlay 폭, Gauge Area 폭, Graph Bar Width, Graph Bar Gap을 변경하면 표시 가능한 시간과 수집 시간이 다시 어긋날 수 있다.

## 채택안

그래프 뷰포트의 실제 물리 픽셀 구조로 표시 가능한 버킷 수를 동적으로 계산한다. 고정된 89개를 사용하는 방식이나 15분 데이터를 시각적으로 늘리는 방식은 사용하지 않는다.

### 공통 계산

하나의 순수 계산 단위가 다음 값을 소유한다.

- 버킷 길이: 15초
- 그래프 왼쪽: `GaugePaneWidth + 4`
- 그래프 오른쪽: `OverlayWidth - 6`
- 막대 슬롯 폭: `GraphBarWidth + GraphBarGap`
- 첫 막대의 왼쪽: `graphRight - GraphBarWidth`
- 표시 가능한 버킷 수: 첫 막대부터 왼쪽 경계 안에 들어오는 슬롯의 수
- 표시 시간: `표시 가능한 버킷 수 × 15초`

기본값 `OverlayWidth=288`, `GaugePaneWidth=100`, `GraphBarWidth=2`, `GraphBarGap=0`에서는 89개 버킷과 1,335초, 즉 22분 15초가 된다.

## 데이터 흐름

1. `ApplicationCoordinator`가 현재 Appearance 설정으로 표시 가능한 버킷 수를 계산한다.
2. 15초마다 실행되는 토큰 활동 폴링이 계산된 수만큼 최근 버킷을 스캐너에 요청한다.
3. 스캐너가 해당 시간 범위의 실제 로그를 집계한다.
4. 렌더러는 동일한 뷰포트 계산을 사용해 오른쪽 최신 데이터부터 전체 영역에 막대를 배치한다.
5. Appearance 설정을 바꾸면 다음 토큰 활동 폴링부터 새로운 전체 시간 범위를 읽는다.

## Appearance 안내

- 위치: Appearance 탭의 수치 설정 목록에서 `Service Status Stripe Width` 다음 마지막 항목
- 영문 문구: `Visible token history: 22 min 15 sec`
- 계산 대상: 현재 편집 세션에서 검증된 Appearance 값
- 갱신 시점: 기존 입력 정책과 동일하게 Enter 또는 포커스 이동으로 값이 반영될 때
- `Reset to Defaults` 실행 시 기본값인 `22 min 15 sec`로 함께 복원
- 0분인 경우에도 분과 초를 모두 표시하여 형식을 안정적으로 유지

## Appearance 숫자 입력 폭

- 현재 숫자 입력 열의 폭 80px를 정확히 60%인 48px로 줄인다.
- `Usage Overlay Width`, `Usage Overlay Height`, `Gauge Area Width`, `Graph Bar Width`, `Graph Bar Gap`, `Service Status Stripe Width`에 같은 폭을 적용한다.
- 입력 상자의 높이, 글꼴, 값 확정 정책, 오른쪽 `px` 단위 표시는 변경하지 않는다.

## 경계 조건

- 유효한 막대 폭은 최소 1px, 간격은 최소 0px인 기존 검증 규칙을 유지한다.
- 그래프에 막대 하나도 들어가지 않는 조합에서는 표시 가능한 시간은 `0 min 0 sec`로 계산한다.
- 스캐너 호출 계약상 양수 버킷 수가 필요한 경우 내부 읽기는 최소 1개를 요청하되, 렌더러와 안내는 실제 표시 가능 개수를 기준으로 한다.
- 실제 토큰 사용이 0인 버킷은 값이 없는 것이 아니라 실제 0 사용 구간이므로 빈 막대로 보이는 기존 표현을 유지한다.

## 테스트

- 기본 Appearance에서 89개와 22분 15초가 계산되는지 검증한다.
- Overlay 폭, Gauge Area 폭, 막대 폭과 간격 변경 시 용량이 정확히 바뀌는지 검증한다.
- `ApplicationCoordinator`가 계산된 버킷 수를 스캐너에 전달하는지 검증한다.
- 안내 문구가 기본값, 설정 변경, 기본값 복원에 맞춰 갱신되는지 검증한다.
- Appearance 숫자 입력 열이 48px이며 모든 숫자 편집 상자에 동일하게 적용되는지 검증한다.
- 렌더러의 막대 배치와 공통 뷰포트 계산이 일치하는지 검증한다.
- 전체 자동화 테스트, 게시, 실제 Windows 11 Appearance 화면 캡처를 수행한다.

## 범위 제외

- 15초 버킷 크기 변경
- 그래프 시간 범위를 별도 사용자 옵션으로 추가
- 5분 구분선 디자인 변경
- 기존 완화 로그 높이와 토큰 색상 보간 방식 변경
