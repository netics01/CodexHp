# CodexHp 물리 픽셀·V1 화면 호환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CodexHp 사용량 오버레이를 Win32/GDI로 전환하고 V1과 같은 `288 × 68px` 물리 크기와 전체화면 기준 위치를 제공한다.

**Architecture:** Core는 사용량 오버레이의 크기·그리기 명령·저장 위치를 정수 물리 픽셀로 계산한다. WPF 애플리케이션과 옵션 창은 유지하고, 같은 Dispatcher 스레드에서 네이티브 Win32 오버레이 창을 생성해 GDI로 그린다. 일반 실행은 화면 왼쪽 `2px`·아래쪽 `12px`, `--compare-v1` 개발 실행은 그보다 창 높이만큼 위에 배치한다.

**Tech Stack:** Windows 11, .NET 10, C#, WPF, Windows Forms NotifyIcon, Win32 User32/GDI32 P/Invoke, xUnit, PowerShell 7, ScreenProof

## Global Constraints

- Windows 11만 지원한다.
- 현재 `master` 작업트리에서 별도 branch와 worktree 없이 작업한다.
- 사용량 오버레이의 모든 크기와 위치는 정수 물리 픽셀이다.
- 기본 외곽 크기는 모든 DPI에서 실제 `288 × 68px`다.
- 제품 기본 위치는 `X = Monitor.Left + 2`, `Y = Monitor.Bottom - 12 - Height`다.
- 개발 비교 위치는 `X = Monitor.Left + 2`, `Y = Monitor.Bottom - 12 - (Height * 2)`다.
- 위치 계산은 `Shell_TrayWnd`나 작업 영역에 의존하지 않는다.
- 사용량 오버레이는 Win32/GDI, 트레이와 옵션 창은 기존 WPF/Windows Forms를 유지한다.
- 기존 인증, 사용량, 그래프 수집, 전체화면 숨김과 정상 종료 동작을 유지한다.
- 기존 Task 16 변경을 보존하고 관련 파일을 함께 검증하되, 마일스톤별로 의도한 파일만 커밋한다.

`UsageOverlayWindow`는 `CS_DBLCLKS` 창 클래스를 등록하고 다음 스타일로 창을 만든다.

```csharp
const uint style = NativeMethods.WsPopup;
const uint extendedStyle = NativeMethods.WsExToolWindow
    | NativeMethods.WsExTopmost
    | NativeMethods.WsExNoActivate;
```

`WM_PAINT`는 현재 레이아웃을 GDI 화가에 전달하고, `WM_ERASEBKGND`는 `1`을 반환한다. `WM_LBUTTONDBLCLK`은 옵션 이벤트를 발행한다. 위치 변경 모드의 `WM_LBUTTONDOWN`은 `ReleaseCapture`와 `SendMessageW(WM_NCLBUTTONDOWN, HTCAPTION)`로 이동한 뒤 실제 창 사각형 이벤트를 발행한다. `SetWindowPos(HWND_TOPMOST, ...)`로 작업표시줄보다 위의 Z 순서를 유지한다. 종료 시 창과 등록 클래스를 해제한다.

`App.OnStartup`은 `--compare-v1`을 대소문자 없이 읽고 첫 배치와 모양 미리보기 복원에 비교 배치 플래그를 전달한다.
