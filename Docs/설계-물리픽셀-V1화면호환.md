# CodexHp 물리 픽셀·V1 화면 호환 설계

## 1. 상태와 목적

- 상태: 사용자 방향 승인 완료, 문서 검토 대기
- 대상 환경: Windows 11
- 목적: CodexHp 사용량 오버레이를 ManaBar V1과 같은 실제 화면 크기와 배치로 렌더링한다.
- 범위: 사용량 오버레이의 렌더링, 크기 단위, 위치 저장, 제품 기본 배치, 개발 비교 배치와 화면 검증
- 제외: 트레이·옵션 창의 WPF 교체, 아이콘 제작, 설치 프로그램과 배포

## 2. 확인된 V1 동작

ManaBar V1은 Windhawk 설정값을 DPI에 따라 변환하지 않고 Win32와 GDI에 정수로 전달한다.

- 창 크기는 `SetWindowPos`와 `CreateWindowExW`에 그대로 전달된다.
- 게이지, 여백, 그래프 막대와 상태 수직바도 GDI `RECT` 좌표에 그대로 전달된다.
- 별도 맵 모드나 좌표 변환이 없으므로 기본 `MM_TEXT`에서 한 좌표 단위는 한 장치 픽셀이다.
- V1의 글자는 `CreateFontW`와 `DrawTextW`로 렌더링된다.

따라서 WPF의 1/96인치 DIP를 사용하는 현재 사용량 오버레이는 Windows 배율이 200%일 때 폭 `288`이 실제 `576px`로 확대된다. V1과 같은 화면을 만들려면 WPF DIP 보정만이 아니라 사용량 오버레이의 좌표와 글자 렌더링을 Win32/GDI 방식으로 맞추는 편이 정확하다.

## 3. 채택한 접근

애플리케이션은 단일 프로세스를 유지하면서 UI 기술을 역할별로 나눈다.

- 트레이, 옵션 창, Dispatcher와 애플리케이션 수명주기: 기존 WPF와 Windows Forms 유지
- 사용량 오버레이 창: Win32 최상위 창
- 사용량 오버레이 그리기: GDI
- 사용량 오버레이 상태와 레이아웃 계산: 기존 Core와 순수 렌더링 모델을 물리 픽셀 의미로 전환

검토 후 채택하지 않은 접근은 다음과 같다.

1. WPF 렌더러에 역 DPI 변환 적용
   - 변경량은 작지만 GDI와 WPF의 글꼴 측정, 기준선과 안티앨리어싱 차이가 남는다.
2. 모든 UI를 Win32로 교체
   - 사용량 오버레이는 정확해지지만 옵션 창까지 다시 구현해야 하므로 현재 목표에 불필요하다.

## 4. 물리 픽셀 좌표 계약

사용량 오버레이와 관련된 모든 숫자는 실제 화면의 물리 픽셀 정수다.

- 창 폭과 높이
- 게이지 영역 폭
- 게이지 높이, 간격과 Refresh 게이지 두께
- 그래프 막대 폭과 간격
- 상태 수직바 폭
- 위치 변경 외곽선 두께
- 창 위치와 저장 좌표

Windows 화면 배율이 100%, 150%, 200%로 바뀌어도 이 값에 배율을 곱하거나 나누지 않는다. 기본 폭 `288`과 높이 `68`은 모든 배율에서 실제 `288 × 68px`다.

WPF 옵션 창은 Per-Monitor DPI Aware V2를 계속 사용한다. 이 규칙은 Win32/GDI 사용량 오버레이에만 적용되며 두 UI 계층 사이에서는 물리 픽셀 값을 변환하지 않고 전달한다.

## 5. V1 호환 기본 모양

사용자가 제시한 현재 V1 실행 설정을 CodexHp 초기값으로 사용한다.

| 항목 | 물리 픽셀 기본값 |
| --- | ---: |
| 사용량 오버레이 폭 | 288 |
| 사용량 오버레이 높이 | 68 |
| 게이지 영역 폭 | 100 |
| 그래프 막대 폭 | 2 |
| 그래프 막대 간격 | 0 |
| 상태 수직바 폭 | 4 |

배경, 내부 여백, 두 게이지와 Refresh 게이지, 그래프 기준선, 5분 구분 점선, 글꼴과 텍스트 정렬은 V1의 GDI 계산식을 기준으로 구현한다. 색상은 제품 요구사항의 V1 기본 색상을 유지한다.

## 6. 위치 모델

### 6.1 좌표 기준

- 좌표의 유일한 기준은 각 모니터의 전체 영역 `Monitor.Bounds`다.
- 작업 영역 `WorkArea`는 사용량 오버레이의 기본 배치나 보정에 사용하지 않는다.
- `Shell_TrayWnd`를 비롯한 작업표시줄 창은 조회하지 않는다.
- 사용량 오버레이가 작업표시줄 위에 보이는 것은 전체화면 물리 좌표 계산의 결과다.

### 6.2 제품 기본 위치

저장 위치가 없는 최초 실행은 주 모니터에 다음 공식으로 배치한다.

```text
Left = Monitor.Left + 2
Top  = Monitor.Bottom - 12 - Height
```

기본 크기에서는 왼쪽 여백 `2px`, 아래쪽 여백 `12px`, 크기 `288 × 68px`다.

### 6.3 개발 비교 위치

V1과 V2를 같은 화면 캡처에서 비교하기 위한 개발 실행 옵션을 제공한다.

```text
Left = Monitor.Left + 2
Top  = Monitor.Bottom - 12 - (Height * 2)
```

기본 크기에서 V2의 하단은 제품 기본 위치의 V1 상단과 맞닿는다. 개발 비교 옵션은 저장된 사용자 위치를 덮어쓰지 않고 해당 실행에만 적용한다.

### 6.4 위치 저장과 복원

- 저장 형식은 모니터 ID와 모니터 전체 영역 좌상단 기준 물리 X/Y 정수다.
- 드래그가 끝나면 `GetWindowRect` 결과를 그대로 상대 좌표로 환산한다.
- DPI가 달라져도 저장값은 변환하지 않는다.
- 저장 모니터가 존재하면 같은 모니터 전체 영역에서 복원한다.
- 저장 모니터가 사라졌거나 창 전체가 화면 밖이면 주 모니터 제품 기본 위치로 복귀한다.
- 부분적으로 화면 밖인 저장 위치는 창 전체가 대상 모니터 영역 안에 들어오도록 보정한다.

## 7. 구성요소와 데이터 흐름

1. `ApplicationCoordinator`가 Core 사용량 오버레이 상태와 현재 설정을 만든다.
2. 순수 레이아웃 계산기가 V1 공식에 따라 물리 픽셀 그리기 명령을 만든다.
3. Win32 오버레이 창이 상태 변경을 받으면 `InvalidateRect`를 호출한다.
4. `WM_PAINT`에서 GDI 화가가 배경, 게이지, 글자, 그래프와 외곽선을 그린다.
5. 더블클릭은 기존 옵션 창 열기 이벤트로 전달한다.
6. 위치 변경 모드의 드래그가 끝나면 실제 창 사각형을 Core 위치 모델에 전달한다.

Win32 창은 WPF Dispatcher와 같은 UI 스레드에서 생성한다. 별도 프로세스, 별도 실행 파일이나 별도 로그인 흐름을 추가하지 않는다.

## 8. 오류와 호환 처리

- Win32 창 생성 실패는 진단 로그에 기록하고 트레이 프로세스를 유지한다.
- GDI 리소스 생성 실패 시 확보된 리소스를 해제하고 다음 화면 갱신에서 재시도한다.
- 설정에 범위를 벗어난 크기 값이 있으면 해당 항목만 V1 호환 기본값으로 복원한다.
- 공개 배포 전 개발 설정에는 논리 좌표가 저장되어 있을 수 있으므로 좌표 의미가 확인되지 않는 기존 값은 제품 기본 위치로 복구한다.
- 인증, 사용량, 전체화면 숨김과 트레이 동작은 이번 변경에서 의미를 바꾸지 않는다.

## 9. 검증 기준

### 9.1 자동 검증

- 100%, 150%, 200% 모니터에서도 배치 결과가 `288 × 68px`다.
- 제품 기본 위치 공식이 모니터 원점과 해상도에 관계없이 왼쪽 `2px`, 아래쪽 `12px`을 만든다.
- 개발 비교 위치가 제품 기본 위치보다 정확히 창 높이만큼 위다.
- 저장 좌표가 DPI 변환 없이 왕복한다.
- 창이 모니터 전체 영역 밖으로 나가면 전체 영역 안으로 보정된다.
- 기본 레이아웃의 게이지 폭, 막대 폭·간격, 기준선과 외곽선이 V1 좌표와 일치한다.

### 9.2 Windows 11 화면 검증

- 개발 비교 옵션으로 V2를 V1 바로 위에 실행한다.
- 전체화면 좌하단을 캡처한다.
- 외곽 `288 × 68px`, 왼쪽 시작점, 배경, 게이지 경계, 백분율 글자, Refresh 게이지, 그래프 막대, 점선과 기준선을 비교한다.
- 차이가 있으면 V1 소스의 GDI 계산을 기준으로 조정하고 다시 캡처한다.
- 제품 기본 실행에서는 같은 좌표가 작업표시줄 창을 조회하지 않고 작업표시줄 위에 표시되는지 확인한다.

## 10. 완료 조건

- 자동 테스트와 빌드가 경고 없이 통과한다.
- V1과 V2 비교 캡처에서 외곽 크기와 주요 내부 좌표가 일치한다.
- 다른 DPI의 모니터에서도 실제 픽셀 크기가 유지된다.
- 제품 기본 위치와 개발 비교 위치가 각각 승인된 전체화면 좌표 공식을 따른다.
- 기존 데이터 수집, 트레이, 옵션, 전체화면 숨김과 정상 종료가 회귀하지 않는다.
