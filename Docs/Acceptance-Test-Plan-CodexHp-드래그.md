# CodexHp 드래그 호스팅 인수테스트 계획

## 목적

이 문서는 CodexHp 위치 변경 드래그의 실제 Windows 호스팅 완료 판정과 검증 방식을 구현 전에 정의한다.

## 기준 문서

| 문서 또는 입력 | 역할 |
| --- | --- |
| `Acceptance-Basis-CodexHp-드래그.md` | 사용자 목표와 완료 기준 |
| `요구사항-CodexHp.md` | 제품 정본 요구사항 |
| `설계-CodexHp-이름변경-이중호스팅.md` | 작업표시줄 자식과 데스크톱 팝업 전환 규칙 |
| `설계-입력-드래그-UI영문화.md` | WPF 표면 재생성과 위치 복구 규칙 |

## 리뷰루프 상태

| 항목 | 내용 |
| --- | --- |
| Review Loop 적용 여부 | 미적용 |
| Review Loop 문서 | 없음 |
| Review Loop 판정 | 주 에이전트 자체 검토에서 실행 가능한 상태 |
| 재리뷰 필요 여부 | 불필요. 요구와 기존 스냅 규칙 사이에 모호성이 발견되면 다시 검토한다. |
| 반영한 주요 자체 검토 | 각 시나리오에 실제 HWND, 부모, 스타일, 물리 사각형, 최상단 적중 HWND와 화면 픽셀을 모두 포함했다. 같은 중간 위치를 양방향 시작 상태로 분리했다. |
| 남은 위험 | 저장소 지침상 다른 에이전트를 사용하지 않으므로 공용 Review Loop의 독립 리뷰어 검토를 수행하지 못했다. 테스트 품질의 독립성은 자체 검토보다 낮다. |

## 검증 범위 조절

| 항목 | 판단 |
| --- | --- |
| 높은 위험 흐름 | `DesktopPopup → TaskbarChild`에서 WPF 합성 표면이 사라졌던 이력이 있으므로 실제 HWND와 화면 픽셀을 함께 검사한다. |
| 낮은 위험 흐름 | 면적 과반 판정, 동률의 내부 선택과 수직 중앙 좌표는 Core 유닛 테스트로 유지한다. |
| 실행 불가 또는 스킵 예정 | 실제 마우스 커서를 이동시키는 자동화는 사용자 작업을 방해하고 Windows 시스템 이동 루프 타이밍에 취약하므로 제외한다. 대신 생산 코드의 드래그 분리·완료 메서드를 실제 창에 호출해 OS 이동 루프 이후의 동일 전환 경로를 검증한다. |
