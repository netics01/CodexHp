# CodexHp 입력·드래그·UI 영문화 설계

## 목적

현재 개발 빌드에서 확인된 다음 문제를 함께 해결한다.

- 사용량 오버레이 더블클릭으로 옵션 창이 열리지 않는다.
- 위치 변경으로 사용량 오버레이를 작업표시줄 밖으로 옮긴 뒤 옵션 창을 취소 방식으로 닫으면 사용량 오버레이가 보이지 않는다.
- 작업표시줄 안과 밖을 오가는 드래그 경로의 실제 렌더링 검증이 부족하다.
- CodexHp가 직접 제공하는 사용자 노출 UI 문구에 한국어가 남아 있다.

## 조사 근거

### 더블클릭 입력

현재 WPF 사용량 오버레이의 창 클래스 스타일에는 `CS_DBLCLKS`가 없다. 따라서 기존 구현이 기다리는 `WM_LBUTTONDBLCLK`가 생성되지 않으며, 두 번의 일반 왼쪽 버튼 입력만 전달된다.

### 취소 후 화면 소실

문제 발생 상태에서도 CodexHp 프로세스와 사용량 오버레이 HWND는 살아 있었다. HWND는 원래 작업표시줄 위치 `(2, 2080, 288 x 68)`에 `Shell_TrayWnd` 자식으로 존재했지만 화면 픽셀은 그려지지 않았다.

현재 표면 재생성은 드래그 메시지 처리 중 `DesktopPopup`에서 `TaskbarChild`로 돌아오는 경로에만 있다. 옵션 창의 `Cancel`, `Esc`, `X`가 미리보기 위치를 원래 위치로 복구할 때는 `SetPlacement`가 같은 호스트 전환을 수행하지만 표면을 재생성하지 않는다.

## 채택 설계

### 1. 더블클릭 인식

- WPF가 계산한 왼쪽 버튼 `ClickCount`를 사용한다.
- `ClickCount == 2`이면 `UsageOverlayWindow.OpenSettingsRequested`를 발생시킨다.
- 일반 상태의 더블클릭은 옵션 창을 연다.
- 위치 변경 모드의 단일 왼쪽 버튼 입력은 기존 Win32 이동 루프를 시작한다.
- Win32 더블클릭 시간과 거리 계산을 CodexHp에서 다시 구현하지 않는다.

### 2. 호스트 전환과 표면 수명

- 사용량 오버레이 배치 경로를 한곳에서 관리한다.
- 최초 배치는 현재 표면을 그대로 사용한다.
- 이미 배치된 표면이 `DesktopPopup`에서 `TaskbarChild`로 전환되면 Dispatcher를 통해 WPF 메시지 처리가 끝난 뒤 표면을 재생성한다.
- 드래그 완료와 옵션 미리보기 복구가 같은 전환 규칙을 사용한다.
- 재생성된 표면은 마지막 물리 좌표, 크기, 모니터, 렌더링 상태, 표시 여부를 복원한다.
- 중복 또는 재귀 재생성을 방지한다.

### 3. 위치 변경 확정·취소 규칙

- `OK`는 이동된 물리 좌표를 저장하고 그 위치를 유지한다.
- `Cancel`, `Esc`, `X`는 모두 편집 전 물리 좌표로 복구한다.
- 복구 위치가 작업표시줄 영역이면 `TaskbarChild`로 돌아가며, 표면 재생성 후 실제 픽셀이 보여야 한다.
- 작업표시줄 밖에서 `OK`로 확정한 위치는 `DesktopPopup`으로 유지한다.

### 4. 사용자 노출 UI 영문화

다음 CodexHp 소유 문구를 영어로 변경한다.

- 옵션 창 제목, 그룹명, 필드명, 체크박스, 안내문, 버튼
- 트레이 메뉴의 Options와 Exit
- 시작 실패와 설정 저장 실패 등 사용자에게 표시되는 오류 메시지

개발자 로그, 테스트 진단 메시지, 코드 내부 예외 문구와 문서는 영문화 범위에서 제외한다. Windows 기본 색상 선택 창처럼 운영체제가 제공하는 UI는 Windows 표시 언어를 따른다.

### 5. 고정 제품 아이콘

- 설치된 `OpenAI.Codex` Windows 패키지에서 256px 공식 비도금 아이콘을 한 번 추출한다.
- 공식 문양의 형태는 바꾸지 않고, 밝은·어두운 작업표시줄에서 모두 식별할 수 있는 짙은 배경판과 하단 빨간 HP 게이지를 결합한다.
- 16px부터 256px까지 필요한 크기를 포함하는 ICO와 원본 크기 PNG를 만든다.
- 32px 프레임의 공식 문양 밝은 픽셀 폭을 최소 26px로 유지해 인접한 공식 Codex 아이콘과 시각적 크기를 맞춘다.
- 결과물을 CodexHp의 고정 자산으로 포함해 실행 파일 아이콘과 트레이 아이콘에 함께 사용한다.
- 실행 중에는 OpenAI 패키지를 찾거나 아이콘을 추출·합성하지 않는다.

## 검증 설계

### 자동 테스트

- 더블클릭 판정이 한 번의 옵션 열기 요청으로 연결되는지 검증한다.
- 단일 클릭이 옵션 열기 요청을 발생시키지 않는지 검증한다.
- 최초 작업표시줄 배치가 불필요한 표면 재생성을 일으키지 않는지 검증한다.
- `TaskbarChild -> DesktopPopup -> TaskbarChild` 왕복 후 HWND 교체와 실제 화면 픽셀을 검증한다.
- 옵션 취소 복구와 동일한 `SetPlacement` 경로에서 작업표시줄 픽셀이 다시 보이는지 검증한다.
- 옵션 그룹과 트레이 메뉴를 포함한 CodexHp 사용자 노출 문자열이 영어인지 검증한다.
- 작업표시줄 안→밖, 밖→안, 안→경계 중간, 밖→경계 중간의 네 시나리오를 실제 Windows 11 HWND로 실행한다.
- 각 시나리오는 최종 HWND, 부모, 스타일, 물리 사각형, `WindowFromPoint` 최상단 적중과 ManaBar 실제 픽셀을 검사한다.
- 32px 제품 아이콘에서 공식 문양의 밝은 픽셀 폭이 26px 이상인지 검증한다.

### 실행 파일 검증

- Windows 11에서 단일 실행 파일을 게시한다.
- 초기 작업표시줄 위치에서 실제 픽셀이 보이는지 확인한다.
- 사용량 오버레이 더블클릭으로 옵션 창이 열리는지 확인한다.
- 위치 변경 후 `Cancel`, `Esc`, `X` 각각에서 원래 위치로 돌아오고 계속 보이는지 확인한다.
- 위치 변경 후 `OK`에서 작업표시줄 밖 위치가 유지되는지 확인한다.
- 다시 작업표시줄 영역으로 이동해 확정했을 때 작업표시줄 자식 호스팅과 실제 픽셀이 유지되는지 확인한다.
- 옵션 창, 트레이 메뉴, 사용자 노출 오류 문구에 CodexHp 소유 한국어가 남지 않았는지 확인한다.
- 게시된 실행 파일과 트레이 아이콘이 임시 시스템 아이콘 대신 고정 CodexHp 아이콘을 사용하는지 확인한다.

## 범위 밖

- 순수 Win32 창으로 사용량 오버레이를 다시 작성하지 않는다.
- 별도의 다국어 리소스 시스템을 도입하지 않는다.
- Windows가 제공하는 시스템 대화상자의 언어를 강제로 변경하지 않는다.
- 설치 프로그램과 시작 프로그램 정책 변경은 이번 변경에 포함하지 않는다.
- 공식 아이콘 자산의 공개 재배포 정책과 상표 검토는 GitHub 공개 전에 별도로 수행한다.
