# CodexHp 드래그 호스팅 인수 기준

## 목적

이 문서는 위치 변경 드래그가 작업표시줄 안과 밖을 오갈 때 사용량 오버레이의 실제 Windows 창, 물리 위치, 표시 픽셀과 Z 순서가 유지되는지를 완료 기준으로 정리한다.

## 요구 입력

| 항목 | 내용 |
| --- | --- |
| 입력 출처 | 2026-08-15 사용자 요청 |
| 원문 요약 | 작업표시줄 안·밖과 경계 중간 위치를 양방향으로 드래그하고, 해당 위치의 HWND·부모·최상단 여부를 런타임 인수테스트로 상시 검증한다. |
| 관련 스펙 | `요구사항-CodexHp.md`, `설계-CodexHp-이름변경-이중호스팅.md`, `설계-입력-드래그-UI영문화.md` |

## 사용자 목표

| ID | 사용자 목표 | 요구 근거 |
| --- | --- | --- |
| G-001 | 사용량 오버레이를 작업표시줄에서 바깥 화면으로 옮겨도 원하는 위치에서 계속 보여야 한다. | 작업표시줄 영역에서 바깥으로 이동하는 시나리오 요청 |
| G-002 | 바깥 화면에서 작업표시줄로 되돌려도 화면이 사라지지 않고 작업표시줄 위에 보여야 한다. | 바깥에서 작업표시줄 안으로 이동하는 시나리오 요청 |
| G-003 | 작업표시줄 경계에 걸쳐 놓더라도 이동 시작 방향과 무관하게 같은 물리 위치 규칙으로 안정적으로 스냅되어야 한다. | 두 방향의 경계 중간 드래그 시나리오 요청 |
| G-004 | 회귀가 생기면 눈으로 우연히 발견하기 전에 자동 테스트가 HWND와 Z 순서 결함을 검출해야 한다. | 기능을 안전하게 상시 유지하라는 요청 |

## 시작 상태와 제약

| ID | 조건 | 설명 |
| --- | --- | --- |
| S-001 | Windows 11 실제 데스크톱 | 가상 창 모델이 아니라 현재 주 모니터와 실제 Windows 작업표시줄 HWND를 사용한다. |
| S-002 | Per-Monitor V2와 물리 픽셀 | 위치와 크기는 DPI 변환 전후의 논리 좌표가 아니라 Win32 화면 물리 좌표로 비교한다. |
| S-003 | 기본 사용량 오버레이 | 검증 크기는 `288 × 68px`이며 불투명 ManaBar 픽셀이 있는 표시 상태를 사용한다. |
| S-004 | 위치 기반 스냅 | 부분 교차는 이동 방향 이력이 아니라 최종 사각형에서 작업표시줄 자식 후보와 바깥 팝업 후보까지의 거리를 비교한다. 동률은 작업표시줄 자식을 선택한다. |

## 완료 기준

| ID | 완료 기준 | 관찰 가능한 결과 |
| --- | --- | --- |
| AC-001 | 작업표시줄 밖 배치 | 부모가 없고 `WS_POPUP`, `WS_EX_TOPMOST`, `WS_EX_TOOLWINDOW`인 실제 HWND가 요구 물리 사각형에 있으며, 내부 검사점의 `WindowFromPoint`가 그 HWND를 반환한다. |
| AC-002 | 작업표시줄 안 배치 | 실제 작업표시줄 HWND가 부모이고 `WS_CHILD`인 새 합성 HWND가 스냅된 물리 사각형에 있으며, 내부 검사점의 `WindowFromPoint`가 그 HWND를 반환한다. |
| AC-003 | 경계 중간 양방향 배치 | 작업표시줄에서 시작한 경우와 바깥에서 시작한 경우 모두 같은 중간 사각형에서 동률 규칙에 따라 작업표시줄 자식 위치로 스냅된다. |
| AC-004 | 렌더링 생존 | 각 최종 위치의 검사점에서 ManaBar 지정 색상의 실제 화면 픽셀이 관찰된다. |
| AC-005 | 상시 회귀 방지 | 네 시나리오가 Windows 전용 xUnit 인수테스트에 포함되고 전체 솔루션 검증에서 반복 실행된다. |

## 열린 질문

없다. 부분 교차의 위치 기반 스냅과 동률 시 작업표시줄 자식 선택은 기존 승인 설계와 Core 테스트에 이미 확정되어 있다.
