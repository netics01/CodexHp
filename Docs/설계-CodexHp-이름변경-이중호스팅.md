# CodexHp 이름 변경·작업표시줄 이중 호스팅 설계

## 1. 문서 목적

- 작성일: 2026-08-15
- 상태: 사용자 승인 설계와 2026-08-15 구현 결과를 반영한 정본
- 목적: 제품 이름을 `CodexHp`로 통일하고, 작업표시줄 내부에서는 반복 클릭에도 가려지지 않으며 화면의 다른 위치에서는 자유롭게 이동할 수 있는 사용량 오버레이 창 관리 방식을 확정한다.
- 적용 범위: 저장소 폴더·프로젝트·코드·문서·실행 파일·런타임 식별자 이름 변경, Win32 사용량 오버레이 호스팅, 드래그 전환, Explorer·DPI 복구, 관련 테스트와 Windows 11 검증
- 비적용 범위: 설치 프로그램 제작, 공개 GitHub 게시, 아이콘 제작, 사용량 초기화 티켓 기능

## 2. 확정 결정

1. 제품 이름은 `CodexHp`다.
2. 저장소의 제품 루트는 ``다.
3. 최종 실행 파일은 `CodexHp.exe`다.
4. 사용량 오버레이의 저장 위치와 크기는 계속 정수 물리 픽셀의 전체 화면 좌표를 사용한다.
5. 제품 기본 위치처럼 창 전체가 작업표시줄 안에 들어가면 사용량 오버레이를 작업표시줄의 자식 HWND로 호스팅한다.
6. 작업표시줄 밖에서는 독립적인 비활성 최상위 팝업 창으로 호스팅한다.
7. 작업표시줄에 부분적으로 걸친 위치는 가장 가까운 완전 내부 또는 완전 외부 위치로 스냅한다.
8. `Shell_TrayWnd`는 호스팅할 작업표시줄을 선택하고 화면 좌표를 자식 좌표로 변환하는 데만 사용한다. 저장 좌표와 제품 기본 배치 공식의 기준은 계속 모니터 전체 화면이다.
9. Deskband11Lib NuGet 패키지를 직접 의존하지 않는다. 공개된 MIT 소스에서 검증한 `WS_CHILD + SetParent` 구조와 WPF 합성 표면 방식을 독립적으로 작게 구현한다.

## 3. 이름 변경 계약

### 3.1 저장소와 빌드 식별자

다음 이름을 일괄 변경한다.

| 대상 | 변경 후 이름 |
| --- | --- |
| 제품 루트 | `` |
| 솔루션 | `CodexHp.slnx` |
| 애플리케이션 프로젝트·어셈블리 | `CodexHp.App`, `CodexHp.exe` |
| Core 프로젝트·어셈블리 | `CodexHp.Core` |
| 테스트 프로젝트 | `CodexHp.App.Tests`, `CodexHp.Core.Tests` |
| C# 루트 네임스페이스 | `CodexHp` |
| 창 클래스와 창 제목 | `CodexHp` |
| 트레이 툴팁 | `CodexHp` |
| 단일 인스턴스 Mutex | `Local\\CodexHp.SingleInstance` |
| 시작 프로그램 레지스트리 값 | `CodexHp` |
| 사용자 설정 루트 | `%LOCALAPPDATA%\\CodexHp` |
| 개발 게시·화면 증거 루트 | `out\\CodexHp` |

파일명과 문서 내부 경로, 스크립트 이름, 테스트 기대값도 같은 이름으로 통일한다. 구현 완료 시 추적 파일과 구현에 사용되는 스크립트에서 이전 제품명 문자열이 한 건도 검색되지 않아야 한다.

### 3.2 기존 개발 데이터

아직 공개 배포 전이므로 이전 개발용 `%LOCALAPPDATA%` 설정과 로그를 자동 이전하지 않는다. 새 실행 파일은 `%LOCALAPPDATA%\\CodexHp`만 읽고 쓴다. 이전 개발 폴더는 읽거나 삭제하지 않으며 사용자가 필요하면 별도로 정리할 수 있게 둔다.

## 4. 창 호스팅 아키텍처

### 4.1 구성요소

- `UsageOverlayWindow`: WPF 합성 오버레이 HWND의 입력, 표시, 배치와 재생성 수명주기를 담당한다.
- `GdiBitmapSourceRenderer`: 물리 픽셀 GDI 명령을 top-down DIB에 그린 뒤 불투명 `Bgr32` WPF `BitmapSource`로 변환한다.
- `WpfOverlaySurface`: 비트맵 표시, WPF `Show/Hide` 수명주기와 `HwndSourceHook` 입력 연결을 담당한다.
- `TaskbarWindowLocator`: 대상 모니터와 일치하는 `Shell_TrayWnd` 또는 `Shell_SecondaryTrayWnd` HWND와 물리 화면 사각형을 찾는다.
- `OverlayHostPlacementCalculator`: 저장된 물리 화면 사각형과 작업표시줄 사각형으로 호스팅 모드, 스냅된 화면 사각형과 자식 좌표를 계산하는 순수 구성요소다.
- `OverlayWindowHost`: 팝업과 작업표시줄 자식 스타일·부모 전환을 담당한다. 제품 상태나 설정 저장은 담당하지 않는다.
- `TaskbarLifecycleMonitor`: Explorer 재시작, 작업표시줄 HWND 교체와 DPI 불일치를 감지하고 오버레이 HWND 재생성을 요청한다.

### 4.2 호스팅 모드

`OverlayHostMode`는 두 값만 가진다.

- `DesktopPopup`
  - 스타일: `WS_POPUP`
  - 확장 스타일: `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE`
  - 부모: `NULL`
  - 좌표: 저장된 전체 화면 물리 좌표를 `SetWindowPos(HWND_TOPMOST, ...)`에 직접 사용
- `TaskbarChild`
  - 스타일: `WS_CHILD`
  - 확장 스타일: `WS_EX_LAYERED`
  - 부모: 대상 모니터의 작업표시줄 HWND
  - 좌표: 저장된 전체 화면 물리 좌표를 `MapWindowPoints(HWND_DESKTOP, taskbarHwnd, ...)`로 변환
  - 자식 형제 순서: `SetWindowPos(HWND_TOP, ...)`로 작업표시줄 내부의 최상단에 배치

작업표시줄 내부에서는 별도 최상위 창 Z-order 경쟁을 하지 않으므로 작업표시줄을 반복해서 클릭해도 사용량 오버레이가 작업표시줄 뒤로 내려가지 않는다.

### 4.3 모드 판정과 스냅

입력은 `desiredOverlayBounds`, `taskbarBounds`와 모니터 전체 사각형이다. 모든 값은 물리 픽셀 정수다.

1. 사용량 오버레이 전체가 작업표시줄 사각형 안에 들어가면 `TaskbarChild`를 선택한다.
2. 두 사각형이 겹치지 않으면 `DesktopPopup`을 선택한다.
3. 부분적으로 겹치면 두 후보를 계산한다.
   - 내부 후보: X는 작업표시줄 안에서 최소 이동하고, Y는 사용량 오버레이가 작업표시줄 높이의 수직 중앙에 오도록 보정한다. 이미 완전히 내부인 위치는 그대로 유지한다.
   - 외부 후보: 창 하단이 작업표시줄 상단과 맞닿도록 위로 이동하고 X는 모니터 전체 안으로 보정한다.
4. 요청 사각형에서 작업표시줄과 겹치는 픽셀 면적과 겹치지 않는 픽셀 면적을 비교해 더 큰 쪽 후보를 선택한다. 면적이 같으면 반복 클릭 안정성을 우선해 내부 후보를 선택한다.
5. 작업표시줄 높이가 사용량 오버레이 높이보다 작아 내부 후보를 만들 수 없으면 외부 후보만 사용한다.

제품 기본 위치는 기존 모니터 전체 좌표 공식으로 먼저 계산한 뒤 이 판정에 전달된다. 저장 위치는 항상 스냅이 끝난 전체 화면 좌표다.

개발용 V1 비교 위치는 작업표시줄과 부분적으로 겹치지 않도록 창 하단을 작업표시줄 상단에 맞춘 `DesktopPopup` 위치를 사용한다. 현재 2160px 높이, 작업표시줄 상단 2064px, 창 높이 68px 조건에서는 Y가 1996px이고 V1 상단과 26px 간격이 생긴다.

## 5. 모드 전환과 드래그

### 5.1 시작과 일반 배치

1. `OverlayPositionController`가 기존처럼 전체 화면 물리 좌표의 배치를 계산한다.
2. `TaskbarWindowLocator`가 해당 모니터의 작업표시줄을 찾는다.
3. `OverlayHostPlacementCalculator`가 호스팅 모드와 최종 화면 좌표를 결정한다.
4. `OverlayWindowHost`가 `SetParent → WS_CHILD` 또는 `WS_POPUP → owner 제거` 순서로 스타일과 부모를 전환한다.
5. `SWP_FRAMECHANGED | SWP_NOACTIVATE`로 프레임과 위치를 적용하고 WPF `Window.Show/Hide`로 최종 가시성을 반영한다.

`SetParent`의 반환값은 이전 부모가 `NULL`이면 성공해도 `NULL`일 수 있으므로, 전환 성공 여부는 마지막 오류만으로 판단하지 않고 `GetParent`와 현재 스타일을 다시 읽어 확인한다.

### 5.2 위치 변경 모드

1. 위치 변경 상태에서 마우스 왼쪽 버튼을 누르면 현재 화면 사각형을 얻는다.
2. 창이 `TaskbarChild`이면 같은 화면 좌표를 유지하면서 `DesktopPopup`으로 분리한다.
3. 자기 HWND에 `WM_NCLBUTTONDOWN(HTCAPTION)`을 보내 Windows 기본 이동 루프를 실행한다.
4. 이동 루프가 끝나면 새 화면 사각형을 모드 판정기에 전달한다.
5. 필요하면 스냅하고 `TaskbarChild`로 다시 결합한다.
6. 결합 또는 팝업 위치 적용이 끝난 뒤에만 `OverlayPositionChanged`를 발행해 설정 작업 사본에 최종 화면 좌표를 저장한다.
7. 팝업 HWND를 그대로 작업표시줄 자식으로 되붙이면 WPF 합성 픽셀이 사라지므로, 내부 결합으로 끝난 경우 마지막 상태·좌표·가시성을 보존한 새 `WpfOverlaySurface`를 생성한다.

취소를 누르면 기존 설정 사본의 화면 좌표로 같은 판정과 전환을 다시 수행한다.

## 6. Explorer, DPI와 표시 복구

### 6.1 Explorer·작업표시줄 수명주기

- `RegisterWindowMessage("TaskbarCreated")` 메시지를 우선 사용한다.
- 1초 저주기 감시에서 작업표시줄 HWND와 오버레이 HWND의 생존 여부를 확인한다.
- Explorer 재시작으로 자식 HWND가 파괴되거나 작업표시줄 HWND가 바뀌면 네이티브 오버레이 창만 새로 만들고 마지막 `UsageOverlayState`, 설정, 물리 위치와 가시성을 다시 적용한다.
- 트레이, 데이터 수집, 옵션 창과 애플리케이션 프로세스는 계속 유지한다.

### 6.2 DPI

- 프로세스의 `PerMonitorV2` 선언을 유지한다.
- 작업표시줄 자식 모드에서도 설정과 저장 좌표는 물리 픽셀로 유지한다.
- `WM_DPICHANGED` 또는 작업표시줄과 오버레이 HWND의 DPI 불일치가 감지되면 화면 좌표를 보존하고 네이티브 오버레이 HWND를 재생성한 뒤 다시 호스팅한다.
- 자식 좌표 변환은 단순 DPI 배율 계산 대신 `MapWindowPoints`를 사용한다.

### 6.3 가시성

기존 전체화면, ChatGPT 실행 조건과 수동 표시 조건이 최종 가시성을 계속 결정한다. 숨김 상태에서는 호스팅 모드를 유지하며 WPF `Window.Hide()`를 적용하고, 조건이 복구되면 활성화하지 않는 WPF 창 설정으로 `Window.Show()`를 적용한다.

## 7. 오류 처리와 안전성

- 작업표시줄을 찾지 못하면 앱 전체를 종료하지 않고 `DesktopPopup`으로 폴백한다.
- 부모·스타일 전환 중 실패하면 마지막으로 유효했던 화면 좌표에서 `DesktopPopup`을 복구한다.
- 교차 프로세스 부모 관계는 Windows가 허용하지만 입력 큐가 결합될 수 있으므로 작업표시줄 HWND에 동기 메시지를 보내지 않는다.
- 오버레이 창 WndProc와 Dispatcher에서는 파일·HTTP 대기를 수행하지 않는다.
- 자식 모드는 작업표시줄 UI를 재배치하거나 수정하지 않으며 사용자가 선택한 물리 좌표에서 불투명 사용량 오버레이으로 기존 픽셀을 덮는다.
- Deskband11Lib 코드를 그대로 복사할 필요가 생기는 경우 MIT 저작권·허가문을 해당 소스 또는 제3자 고지에 보존한다. Win32 동작을 독립 구현하는 경우에도 조사 근거는 개발 문서에 남긴다.

## 8. 테스트와 Windows 11 검증

### 8.1 자동 테스트

- 이름 변경 후 솔루션의 모든 프로젝트가 새 이름으로 복원·빌드·테스트된다.
- 추적 파일과 제품 스크립트에서 이전 제품명 검색 결과가 0건이다.
- 완전 내부, 완전 외부, 부분 교차, 같은 거리, 작업표시줄보다 큰 창의 모드·스냅 계산을 단위 테스트한다.
- 화면 좌표와 작업표시줄 자식 좌표의 변환 계약을 테스트한다.
- 자식에서 드래그 시작 시 팝업으로 분리되고 이동 종료 후 최종 위치가 한 번만 저장되는 계약을 테스트한다.
- 실제 화면 `GetPixel`로 작업표시줄 자식, 데스크톱 팝업과 새 작업표시줄 자식 표면에 동일한 지정 색상이 합성되는지 테스트한다.
- GDI DIB가 투명 `Bgra32`로 남지 않고 불투명 `Bgr32`로 변환되는지 테스트한다.
- 옵션 창 시스템 닫기가 동기 `Close()` 재진입 없이 취소를 한 번 적용하고 창만 닫는지 테스트한다.
- 작업표시줄 검색 실패와 전환 실패가 팝업 폴백으로 끝나는 계약을 테스트한다.
- 기존 렌더링, 설정 취소 복원, 전체화면 가시성, 트레이와 정상 종료 테스트를 유지한다.

### 8.2 실제 화면 검증

1. Windows 11에서 V1과 개발 비교 실행을 함께 캡처해 `288 × 68` 물리 픽셀과 그래프 모양을 비교한다.
2. 제품 기본 모드로 실행해 오버레이 HWND의 부모가 대상 `Shell_TrayWnd`이고 창 전체가 작업표시줄 내부인지 확인한다.
3. 작업표시줄의 빈 영역과 여러 앱 버튼을 연속해서 클릭한 뒤 사용량 오버레이가 한 번도 가려지지 않는지 화면 캡처와 HWND 상태로 확인한다.
4. 위치 변경 모드에서 작업표시줄 밖으로 드래그해 `DesktopPopup`이 되고 일반 창을 가리는지 확인한다.
5. 다시 작업표시줄 안으로 드래그해 `TaskbarChild`로 결합되고 반복 클릭에 안정적인지 확인한다.
6. 경계에 놓아 내부 또는 외부로 스냅되는지 확인한다.
7. 같은 모니터의 전체화면에서 숨고 전체화면 종료 후 원래 호스팅 모드로 복구되는지 확인한다.
8. Explorer 재시작과 디스플레이 배율 변경 후 프로세스를 다시 시작하지 않아도 사용량 오버레이가 재생성되는지 확인한다.
9. 자기 포함 단일 파일 게시 결과가 `CodexHp.exe` 하나인지 확인한다.

ScreenProof 증거는 무시된 `out/screenproof/` 아래에 저장하고 스크린샷, `meta.json`, `windows.json`을 함께 판독한다.

2026-08-15 구현 검증에서는 `latest-build-visible/` 전체 화면 캡처와 좌하단 확대에서 제품 기본 영역을 직접 확인했다. 게시 검증은 HWND·부모·스타일뿐 아니라 내부 픽셀과 주변 작업표시줄 픽셀의 차이도 검사한다. Explorer 재시작과 디스플레이 배율 변경처럼 시스템 상태를 크게 바꾸는 실제 검증은 수행하지 않고 자동 복구 계약 테스트만 유지했다.

## 9. 완료 기준

- 저장소의 제품 폴더, 프로젝트, 네임스페이스, 실행 파일, 런타임 경로와 사용자 표시명이 `CodexHp`로 통일된다.
- 기존 기능 테스트와 새 호스팅 테스트가 모두 통과한다.
- 제품 기본 위치의 사용량 오버레이는 작업표시줄 클릭으로 가려지지 않는다.
- 자유 위치에서는 기존처럼 일반 창 위에 표시되고 위치 변경 모드에서만 드래그된다.
- 작업표시줄 경계에서는 부분 교차 상태가 저장되지 않는다.
- Explorer·DPI 변화, 전체화면 숨김과 복구가 앱 프로세스 종료 없이 동작한다.
- Windows 11 자기 포함 단일 파일 `CodexHp.exe`로 실행된다.
