# CodexHp 옵션 창 Alt+Tab 및 완화 로그 토큰 그래프 설계

## 1. 목적

두 가지 사용자 동작을 변경한다.

1. 열려 있는 `CodexHp Settings` 창을 Windows Alt+Tab 목록에 표시한다.
2. 큰 초기 컨텍스트 토큰 스파이크가 존재해도 평상시 토큰 활동이 그래프에서 식별되도록 막대 높이를 완화 로그 방식으로 계산한다.

사용량 오버레이, 숨은 트레이 메시지 창, 데이터 수집 방식, 15초 버킷 60개의 15분 표시 범위와 토큰별 색상 보간은 변경하지 않는다.

## 2. 조사 근거

실제 `.codex` 기록을 현재 `CodexTokenUsageScanner`로 읽은 결과는 다음과 같았다.

- 최근 15분: 60개 버킷 중 59개가 0보다 컸고, 중앙값은 `3,677`, 최대값은 `45,172` 토큰으로 최대/중앙값 비율이 `12.29`였다.
- 최근 60분: 0보다 큰 버킷의 중앙값은 `3,578`, 최대값은 `113,468` 토큰으로 최대/중앙값 비율이 `31.71`이었다.
- 기본 높이 `58px`에서 최대값이 `113,468`이면 선형 축의 `3,677` 토큰은 약 `1px`에 불과하다.

순수 로그는 수십 토큰도 지나치게 크게 보이게 하므로 채택하지 않는다. 최대값을 잘라내는 방식은 스파이크의 실제 상대 크기를 잃으므로 채택하지 않는다.

## 3. 옵션 창 Alt+Tab 동작

`CodexHp Settings`는 일반 애플리케이션 창으로 취급한다.

- XAML `ShowInTaskbar`는 `True`다.
- HWND 생성 직후 `WS_EX_TOOLWINDOW`를 제거하고 `WS_EX_APPWINDOW`를 설정한다.
- 기존 옵션 창 단일 인스턴스, 확인·취소, 닫기 버튼 수명주기는 유지한다.
- 사용량 오버레이는 기존처럼 `WS_EX_TOOLWINDOW`를 설정하고 `WS_EX_APPWINDOW`를 제거한다.
- 숨은 트레이 메시지 창도 기존 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`를 유지한다.

`AltTabWindowStyle`에 표시용 순수 계산 함수와 적용 함수를 추가한다. 기존 숨김 함수는 오버레이의 호환성을 위해 그대로 유지한다.

## 4. 완화 로그 높이

토큰 버킷 값 `v`, 현재 화면에 보이는 최대 버킷 `M`, 그래프 가용 높이 `H`, knee `K=10,000`일 때 다음 식을 사용한다.

```text
height(v) = H × log(1 + v / K) / log(1 + M / K)
```

정수 픽셀 변환 규칙은 다음과 같다.

- `v <= 0`, `M <= 0`, `H <= 0`이면 `0px`다.
- `v > 0`이면 계산 결과를 내림하고 최소 `1px`을 보장한다.
- `v >= M`이면 `H`를 반환해 최대 막대가 가용 높이를 넘지 않게 한다.
- `K=10,000`은 코드 상수로 고정하며 이번 범위에서는 설정 옵션을 추가하지 않는다.

기본 `H=58`, `M=45,172`일 때 대표 높이는 `1K→3px`, `3,677→10px`, `5K→13px`, `10K→23px`, `20K→37px`, `45,172→58px`다.

높이와 색상의 의미를 분리한다.

- 높이: 완화 로그를 사용해 활동 패턴 가독성을 높인다.
- 색상: 기존 `TokenColorInterpolator`의 실제 토큰 `10K~100K` 선형 보간을 유지해 절대 사용량 강도를 보완한다.

## 5. 코드 경계

- `CodexHp.Core.Domain.TokenGraphHeightScaler`: UI와 무관한 완화 로그 픽셀 계산만 담당한다.
- `UsageOverlayRenderer`: 화면 내 최대 버킷과 가용 높이를 전달하고 반환된 높이로 막대를 배치한다.
- `AltTabWindowStyle`: 숨김용과 표시용 Win32 확장 스타일 계산·적용을 담당한다.
- `SettingsWindow`: 표시용 Alt+Tab 스타일을 선택한다.

## 6. 검증

- Core 단위 테스트가 대표 관측값, 0, 최대값, 최대값 초과와 높이 0을 검사한다.
- 렌더러 테스트가 `45,172` 스파이크와 `3,677` 평상시 버킷을 각각 `58px`, `10px`로 배치하는지 검사한다.
- 실제 WPF 옵션 HWND 테스트가 `WS_EX_APPWINDOW=설정`, `WS_EX_TOOLWINDOW=제거`와 `ShowInTaskbar=true`를 검사한다.
- 기존 오버레이 Alt+Tab 제외 테스트는 변경하지 않는다.
- 전체 테스트와 self-contained single-file 게시 후 실제 게시본에서 옵션 창 HWND 스타일을 다시 확인한다.

## 7. 옵션 창 높이 추가 변경

사용자의 추가 요청에 따라 옵션 창의 논리 높이를 기존 `590`에서 15% 줄인 뒤 가장 가까운 정수로 맞춘다.

```text
590 × 0.85 = 501.5 → 502
```

- `Height`와 `MinHeight`를 모두 정수 `502`로 설정한다.
- 논리 폭 `650`, 좌우 영역 폭, 여백, 행 높이와 버튼 크기는 변경하지 않는다.
- 고정 높이 내부에서 왼쪽 그룹 목록과 오른쪽 옵션 패널은 계속 같은 상단·하단 기준선을 사용한다.
- 200% DPI 환경의 예상 물리 높이는 `1004px`이며 실제 게시 창 캡처로 잘림 여부를 확인한다.
