| 상태 수직바 | OpenAI 서비스 장애 또는 상태 확인 실패를 사용량 오버레이 왼쪽에 표시하는 수직 막대 |
| 토큰 사용량 그래프 | 로컬 Codex 활동을 짧은 시간 구간으로 집계해 사용량 오버레이 오른쪽에 표시하는 막대 그래프 |

## 3. 제품 목표

CodexHp는 ChatGPT 데스크톱 앱에서 Codex를 정상적으로 사용 중인 Windows 11 사용자가 별도 설정 없이 실행하여 Codex 사용량을 계속 확인할 수 있게 하는 도구다.

제품 경험의 기준은 다음과 같다.

- 사용자는 ChatGPT 데스크톱 앱의 설치와 로그인 외에 CodexHp용 계정 설정을 하지 않는다.
- CodexHp를 실행하면 트레이 아이콘이 생기고 사용량 오버레이가 기본 위치에 표시된다.
- 사용자는 트레이 아이콘이나 사용량 오버레이에서 옵션 창을 열어 동작과 모양을 변경할 수 있다.
- Windhawk나 Codex CLI 같은 별도 런타임 도구를 설치하지 않는다.
- 일반 사용자와 설치를 수행하는 에이전트 모두 같은 최종 설치 상태를 얻을 수 있다.

## 4. 지원 범위와 제외 범위

### 4.1 지원 범위

- Windows 11 빌드 22000 이상만 지원한다.
- ChatGPT 데스크톱 앱에 통합된 Codex 사용자를 지원한다.
- ChatGPT 앱에서 시작한 Codex 작업을 포함해 Codex 계정 한도, 초기화 시간, 로컬 Codex 토큰 활동을 표시한다.
- .NET 런타임을 별도로 요구하지 않는 단일 실행 파일을 기본 애플리케이션 산출물로 제공한다.
- 단일 실행 파일은 self-contained 게시를 유지하고 내부 관리 런타임을 압축한다.
- 게시에는 중립 영문 리소스와 한국어 위성 리소스만 포함하며 그 밖의 프레임워크 위성 지역화 리소스는 제외한다.
- WPF의 XAML·리플렉션 동작을 보존하기 위해 어셈블리 트리밍은 사용하지 않는다.
- `win-x64` 핵심 게시의 `CodexHp.exe` 크기는 `100 MiB` 이하여야 한다.

### 4.2 제외 범위

- OpenCode를 지원하지 않는다.
- Codex CLI만 설치된 환경을 지원 대상으로 삼지 않는다.
- Codex가 아닌 일반 ChatGPT 대화의 토큰 사용량은 수집하거나 표시하지 않는다.
- Windhawk를 사용하지 않는다.
- CodexHp가 ChatGPT 로그인 또는 OAuth 인증을 직접 진행하지 않는다.
- 사용량 초기화 티켓의 조회, 표시, 사용 기능은 구현하지 않는다. 가능성 조사만 보존하며 당분간 제품 범위에 추가하지 않는다.
- ChatGPT 데스크톱 앱과 Codex가 정상적으로 동작하지 않는 환경을 대신 복구하지 않는다.
- Windows 11 이외 플랫폼의 설치, 실행, 검증은 범위에 포함하지 않는다.

## 5. 인증과 사용량 연결

### 5.1 연결 원칙

- 사용량 연결은 ManaBar V1 방식을 유지한다.
- CodexHp는 `%CODEX_HOME%\auth.json` 또는 `%USERPROFILE%\.codex\auth.json`에서 기존 Codex 인증 캐시를 읽는다.
- 인증 캐시의 `access_token`과 선택적 `account_id`를 사용해 ChatGPT의 Codex 사용량 엔드포인트를 직접 조회한다.
- 사용량 조회의 현재 기준 경로는 `https://chatgpt.com/backend-api/wham/usage`이다.
- 인증 캐시가 없거나 읽을 수 없으면 로그인 창을 열지 않고 대기 상태를 표시한다.
- 대기 중에도 인증 캐시를 주기적으로 다시 확인하며, 사용자가 ChatGPT 앱에서 정상 인증을 완료하면 자동으로 기본 기능을 시작한다.
- CodexHp는 로그인 토큰을 자체 설정 파일이나 로그에 복사하여 저장하지 않는다.

### 5.2 인증 전제

지원 사용자는 다음 조건을 충족한다고 가정한다.

- ChatGPT 데스크톱 앱이 설치되어 있다.
- ChatGPT 데스크톱 앱에서 로그인되어 있다.
- ChatGPT 앱의 Codex 기능이 온라인에서 정상적으로 동작한다.

이 전제가 충족되는데도 CodexHp가 인증 캐시를 발견하지 못하는 경우는 제품 결함 또는 호환성 문제로 진단한다.

### 5.3 데이터 갱신

- 인증 부재 상태에서도 프로세스와 트레이 아이콘은 유지된다.
- 인증과 사용량 데이터는 장기 실행 중 주기적으로 다시 읽는다.
- 일시적인 네트워크 실패가 발생해도 프로세스를 종료하지 않고 다음 주기에 재시도한다.
- 로컬 토큰 그래프 수집 실패와 서버 한도 조회 실패를 서로 독립된 상태로 취급한다.

## 6. 설치와 실행 수명주기

### 6.1 최종 설치 상태

- 최종 애플리케이션 경로는 `%LOCALAPPDATA%\CodexHp.exe`이다.
- 사용자별 설치를 기본으로 하며 관리자 권한 없이 설치할 수 있어야 한다.
- 설치가 완료되면 Windows 시작 프로그램에 기본적으로 등록한다.
- 사용자는 일반 옵션에서 시작 프로그램 등록을 해제하거나 다시 등록할 수 있다.

### 6.2 배포 경로

이 절은 기능 구현과 검증을 완료한 뒤 진행할 배포 마일스톤의 확정된 방향을 기록한다. 현재 핵심 기능 구현 범위에는 설치 프로그램, 설치 스크립트, 공개 저장소 배포를 포함하지 않는다.

배포 마일스톤에서는 서로 다른 두 설치 진입점을 제공하되 최종 설치 경로와 실행 상태는 같아야 한다.

1. Windows 표준 설치 프로그램
    - Inno Setup으로 `CodexHp-Setup.exe`를 만든다.
    - 일반 사용자가 익숙한 설치 UI를 제공한다.
    - 설치, 실행, 제거, 시작 프로그램 등록을 표준적인 흐름으로 제공한다.
2. 에이전트 친화적 설치 방식
    - `Install-CodexHp.ps1`을 제공한다.
    - 사용자가 에이전트에게 설치를 지시했을 때 표준 설치 프로그램을 비대화형으로 실행하고 결과를 검증하기 쉬워야 한다.
    - 명시적인 설치 경로와 종료 코드를 제공해야 한다.
    - 최종적으로 표준 설치 프로그램과 같은 애플리케이션 파일과 시작 프로그램 등록 상태를 만든다.

설치 로직의 정본은 Inno Setup으로 만든 `CodexHp-Setup.exe` 하나로 유지한다. PowerShell 설치 스크립트는 설치 로직을 복제하지 않고 Inno Setup의 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` 인터페이스를 호출하며, 설치 후 `%LOCALAPPDATA%\CodexHp.exe`와 시작 프로그램 등록 상태를 검증한다.

PowerShell 스크립트가 설치 프로그램을 확보하는 방식은 기능 검증과 공개 GitHub 저장소 준비가 끝난 뒤 확정한다.

### 6.3 구현과 배포 순서

1. CodexHp 핵심 기능을 구현한다.
2. Windows 11에서 핵심 기능과 사용자 동작을 검증한다.
3. 기능이 안정된 뒤 트레이·실행 파일용 최종 아이콘을 한 번 제작해 고정 자산으로 탑재한다.
4. 설치 프로그램과 에이전트용 설치 스크립트를 구현한다.
5. 설치 경로까지 검증한 뒤 공개 GitHub 저장소 배포 방식을 결정한다.

## 7. 트레이 동작

- 프로그램이 실행되면 Windows 알림 영역에 트레이 아이콘을 표시한다.
- 트레이 아이콘과 메뉴는 Windows Forms를 사용하지 않고 숨은 WPF 메시지 HWND, `Shell_NotifyIconW`와 Win32 팝업 메뉴 API로 구현한다.
- 트레이 아이콘을 좌클릭하면 옵션 창을 바로 연다.
- 트레이 아이콘을 우클릭하면 `옵션`과 `종료` 항목이 있는 컨텍스트 메뉴를 표시한다.
- 우클릭 메뉴의 `옵션`은 옵션 창을 열고, `종료`는 CodexHp 프로세스를 정상 종료한다.
- 최종 아이콘은 설치된 공식 `OpenAI.Codex` 패키지의 256px 비도금 아이콘을 개발 시 한 번 추출해 제작한다.
- 원본 문양 아래에는 사용량 게이지를 뜻하는 빨간 HP 게이지를 결합한다.
- 완성한 결과는 CodexHp의 고정 자산으로 탑재하며 실행 중 동적으로 아이콘을 추출하거나 합성하지 않는다.
- 공식 문양은 인접한 공식 Codex 트레이 아이콘과 비슷한 시각적 크기로 표시하면서도 하단 HP 게이지가 구분되어야 한다.
- 32px 프레임에서 공식 문양의 밝은 픽셀 폭은 최소 `26px`이어야 한다.
- 아이콘 추출·변형·재배포에 관한 상표와 저작권 위험은 배포 전에 별도로 확인한다.
- 색상 `Pick`은 Windows Forms를 사용하지 않고 owner HWND가 지정된 Win32 `ChooseColorW` 대화상자를 연다. 취소하면 현재 색상을 변경하지 않는다.

## 8. 사용량 오버레이

### 8.1 기본 표시

- 최초 실행 시 주 모니터 전체 영역의 좌하단에 나타나며 작업표시줄 위를 덮는다.
- 제품 기본 위치는 주 모니터 전체 영역의 물리 좌표를 기준으로 왼쪽 `2px`, 아래쪽 `12px` 여백을 둔다.
- 기본 크기는 실제 화면에서 `288 × 68px`이며 Windows 화면 배율에 따라 확대하거나 축소하지 않는다.
- 사용량 게이지와 토큰 사용량 그래프를 V1과 같은 좌표와 밀도로 표시한다.
- 사용량 오버레이는 물리 픽셀 GDI 비트맵을 WPF 합성 표면에 표시한다. 작업표시줄 내부에서는 자식 HWND, 외부에서는 최상위 팝업 HWND로 같은 표면을 호스팅한다.
- 사용량 오버레이는 작업표시줄 내부·외부 호스팅 상태와 드래그 전환 중에도 Windows Alt+Tab 목록에 나타나지 않는다.
- 사용량 오버레이는 뒤쪽 창을 가리는 일반적인 최상위 표시 영역이며 마우스 클릭을 뒤쪽 창으로 통과시키지 않는다.
- 사용량 오버레이는 V1과 같은 불투명 배경색 `#18181C`를 사용한다.
- 평상시 한 번 클릭과 드래그에는 동작을 연결하지 않는다.
- 사용량 오버레이를 더블클릭하면 옵션 창을 연다.
- 사용량 오버레이 드래그 이동은 옵션 창의 `Overlay Position` 그룹이 선택된 동안에만 허용한다.
- 사용자가 확정한 위치는 다음 실행 때 복원한다.
- 저장된 모니터가 없거나 위치가 화면 밖이면 주 모니터의 제품 기본 위치로 안전하게 복귀한다.
- 위치는 모니터 식별자와 해당 모니터 전체 영역 좌상단 기준 물리 X/Y 정수로 저장한다.
- 모니터 DPI 또는 화면 배율이 바뀌어도 저장된 크기와 위치를 확대하거나 축소하지 않는다.
- 화면 밖으로 나간 부분은 작업 영역이 아니라 모니터 전체 영역 안으로 보정하여 작업표시줄 위 배치를 허용한다.
- 저장 좌표와 제품 기본 배치 공식은 모니터 전체 영역을 기준으로 한다. `Shell_TrayWnd` 좌표는 작업표시줄 내부 호스팅 여부, 부분 교차 스냅과 자식 좌표 변환에만 사용한다.
- 사용량 오버레이가 작업표시줄 경계와 부분적으로 겹치면 작업표시줄과 겹친 픽셀 면적과 바깥 픽셀 면적 중 더 큰 쪽으로 스냅한다. 두 면적이 같으면 작업표시줄 내부를 선택한다.
- 바깥쪽 스냅은 사용량 오버레이 하단을 작업표시줄 상단에 맞대고, 안쪽 스냅은 사용량 오버레이를 작업표시줄 높이의 수직 중앙에 배치한다. 이미 완전히 내부에 놓인 위치는 변경하지 않는다.
- 개발 비교 실행에서는 제품 기본 위치보다 정확히 `68px` 위에 배치하여 V1과 같은 X축에서 두 화면이 맞닿게 한다.

### 8.2 표시 조건

- 일반 옵션에서 `ChatGPT 실행 중에만 표시`와 `항상 표시` 중 하나를 선택할 수 있다.
- 최초 실행의 기본값은 `항상 표시`이다. 사용자가 프로그램 실행 결과를 즉시 인식할 수 있도록 인증이나 사용량 데이터가 아직 준비되지 않은 상태도 사용량 오버레이에 표시한다.
- `ChatGPT 실행 중`은 공식 `OpenAI.Codex` Windows 앱 패키지 내부의 `ChatGPT.exe` 프로세스가 하나 이상 존재하는 상태로 판정한다.
- 외부 Codex CLI 프로세스는 표시 조건에 영향을 주지 않는다.
- ChatGPT 앱에서 수행하는 Codex 작업도 Codex 사용량을 소비할 수 있으므로 `codex.exe` 하위 프로세스만을 표시 조건으로 사용하지 않는다.
- 사용량 오버레이가 놓인 모니터를 덮는 전체 화면 애플리케이션을 감지하면 선택한 표시 조건과 무관하게 사용량 오버레이를 자동으로 숨긴다.
- 다른 모니터에서만 전체 화면 애플리케이션이 실행 중이면 사용량 오버레이를 계속 표시한다.
- 전역 전체 화면 또는 프레젠테이션 알림만으로 숨기지 않고, 실제 전체 화면 창과 사용량 오버레이의 모니터가 같은지 확인한다.
- 전체 화면 상태가 끝나면 원래 표시 조건에 따라 다시 표시한다.
- 트레이 아이콘은 사용량 오버레이가 숨겨져 있어도 유지된다.

### 8.3 Overlay Position 모드

- 옵션 창의 `Overlay Position` 그룹을 선택하면 오른쪽 내용 영역에는 `Drag the usage overlay to the desired location.` 안내만 표시한다.
- `Overlay Position` 그룹이 선택된 동안 사용량 오버레이 가장자리에 두께 `4px`의 외곽선을 표시한다.
- 사용자는 강조된 사용량 오버레이를 직접 드래그해 원하는 화면 위치로 옮긴다.
- 다른 옵션 그룹으로 이동하거나 옵션 창을 닫으면 `Overlay Position` 외곽선을 제거한다.
- `확인`을 누르면 새 위치를 저장하고 `취소`를 누르면 옵션 창을 열기 전 위치로 되돌린다.

## 9. 옵션 창

### 9.1 공통 구조

- 왼쪽에는 옵션 그룹을 선택하는 세로 탭 목록을 배치한다.
- 오른쪽에는 선택한 그룹의 옵션을 배치한다.
- 창 아래에는 `확인`과 `취소` 버튼을 제공한다.
- 옵션 창은 Windows 11 시스템의 밝은·어두운 테마를 자동으로 따르며, 픽픽 옵션 창과 같은 조밀한 데스크톱 설정 화면 밀도를 기준으로 한다.
- 100% DPI 논리 크기의 기본 창은 `650 × 502`다. 기존 높이 `590`의 15% 축소값 `501.5`를 가장 가까운 정수로 맞췄으며, 바깥 여백은 `10`, 왼쪽 그룹 목록 폭은 `130`, 목록과 내용 사이 간격은 `10`이다.
- 그룹 항목 높이는 `30`, 오른쪽 섹션 헤더 높이는 `28`, 본문 안쪽 여백은 `10`, 확인·취소 버튼은 각각 `92 × 26`으로 유지한다.
- 기본 글꼴은 `Segoe UI 13`, 섹션 제목은 `14 SemiBold`이며, 패널과 버튼은 각진 얇은 외곽선과 중립색 선택 상태를 사용한다.
- 왼쪽 그룹 목록과 오른쪽 옵션 패널은 동적 창 높이를 사용하지 않으므로 같은 상단·하단 기준선과 같은 높이를 유지한다.
- 옵션 창 자체에 `ThemeMode=System`을 적용하고 사용자 정의 패널·탭·버튼은 현재 WPF Fluent 테마의 의미 기반 배경·글자 리소스를 사용한다. 레거시 Windows 시스템 색상은 직접 지정하지 않는다.
- 옵션 창의 닫기 버튼과 `Esc`는 `취소`와 동일하게 동작한다.
- 옵션 창의 닫기 버튼은 취소 처리를 마친 뒤 옵션 창만 닫아야 하며 CodexHp 프로세스를 종료하거나 WPF 닫기 재진입 예외를 일으키면 안 된다.
- 옵션 창이 열려 있는 동안 `CodexHp Settings`는 일반 앱 창처럼 Windows Alt+Tab 목록과 작업표시줄에 나타난다. 사용량 오버레이와 숨은 트레이 메시지 창은 계속 나타나지 않는다.
- `Colors`, `Appearance`, `Overlay Position`의 변경 사항은 사용량 오버레이에 즉시 미리보기로 적용한다.
- `확인`은 미리보기 값을 확정해 저장하고, 일반 그룹의 시작 프로그램 등록과 표시 조건을 적용한다.
- `취소`는 색상, 모양, 위치를 옵션 창을 열기 전 값으로 되돌리고 아무 변경도 저장하지 않는다.
- 일반 그룹의 시작 프로그램 등록과 표시 조건은 실시간 미리보기하지 않고 `확인`을 누를 때만 적용한다.
- 옵션 수가 늘어나더라도 관련 옵션을 기존 그룹에 배치하거나 명확한 새 그룹을 만들어 관리한다.

### 9.2 일반 그룹

- Windows 시작 시 CodexHp 실행
    - 기본값: 사용
- 사용량 오버레이 표시 조건
    - `ChatGPT가 실행 중일 때만 표시` 체크박스를 제공한다.

### 9.3 색상 그룹

모든 색상 값은 컬러 피커로 변경할 수 있어야 한다.

- 색상 그룹 하단에 `Reset to Defaults` 버튼을 제공한다.
- 이 버튼은 색상 7개만 V1 기준 기본값으로 변경하고 즉시 미리보기한다. 일반, 모양, 위치 설정은 변경하지 않는다.
- 초기화 결과는 `확인`을 눌러야 저장되며 `취소`, 닫기 버튼 또는 `Esc`를 사용하면 옵션 창을 열기 전 색상으로 복원한다.
- 각 색상 견본은 `24 × 24px`로 `Pick` 버튼 높이와 맞추고, `Pick` 버튼은 `44 × 24px`의 간결한 크기로 표시한다.

| UI 라벨 | V1 기준 기본값 |
| --- | --- |
| `ManaBar: Token Limit Gauge for 5 Hours` | `#3A8EFF` |
| `HpBar: Token Limit Gauge for One Week` | `#DC4856` |
| `Refresh Gauge: Time Remaining Until Token Limit Reset` | `#FFFFFF` |
| `Issue Stripe: OpenAI Service Issue Detected` | `#F5A623` |
| `Unknown Stripe: Unable to Check OpenAI Service Status` | `#808080` |
| `Token Graph Low: ≤10K Tokens per 15s` | `#2667CD` |
| `Token Graph High: ≥100K Tokens per 15s` | `#DC4856` |

- 토큰 그래프 막대 색상은 낮은 사용량 색상과 높은 사용량 색상 사이를 선형 보간한다.
- 사용량 임계값의 V1 기준은 낮음 `10,000`, 높음 `100,000` 토큰이다.

### 9.4 모양 그룹

V1에서 Windhawk에 노출했던 다음 숫자 설정을 편집할 수 있어야 한다. 기본값은 사용자가 비교 기준으로 제시한 V1 실행 설정과 일치한다.

모든 크기 값은 실제 화면의 물리 픽셀이다. Windows 화면 배율과 관계없이 설정값 `1px`은 실제 화면 픽셀 한 칸으로 렌더링한다.

- 옵션 창의 여섯 숫자 항목 모두 크기 단위를 `Physical px`가 아니라 `px`로 표시하되 값의 물리 픽셀 의미는 바꾸지 않는다.
- 여섯 숫자 입력 TextBox의 편집 열 폭은 `48px`로 통일한다. 이는 기존 `80px`의 60%다.
- 숫자 TextBox의 caret은 현재 시스템 테마의 기본 글자색을 사용해 밝은·어두운 입력 배경 모두에서 명확히 보여야 한다.
- 숫자를 편집하는 동안에는 작업 사본과 사용량 오버레이를 갱신하지 않는다. `Enter`를 누르거나 입력 필드가 포커스를 잃을 때 해당 값의 변환·범위 검사와 즉시 미리보기를 수행한다.
- 모양 그룹 하단에 `Reset to Defaults` 버튼을 제공한다. 이 버튼은 모양 값만 기본값으로 변경하고 즉시 미리보기하며 일반, 색상, 위치 설정은 보존한다.
- 모양 초기화 결과는 `확인`을 눌러야 저장되며 `취소`, 닫기 버튼 또는 `Esc`를 사용하면 옵션 창을 열기 전 값으로 복원한다.

| 항목 | 기본값 | 허용 범위 | 의미 |
| --- | ---: | ---: | --- |
| 사용량 오버레이 폭 | `288px` | `120–4096px` | 전체 표시 영역의 폭 |
| 사용량 오버레이 높이 | `68px` | `24–512px` | 전체 표시 영역의 높이 |
| 게이지 영역 폭 | `100px` | `20px–(사용량 오버레이 폭−20px)` | 왼쪽 ManaBar/HpBar 영역의 폭 |
| 그래프 막대 폭 | `2px` | `1–20px` | 토큰 그래프 막대 하나의 폭 |
| 그래프 막대 간격 | `0px` | `0–20px` | 토큰 그래프 막대 사이 간격 |
| 상태 수직바 폭 | `4px` | `1–12px` | 장애 상태 수직바의 폭 |

- 숫자 입력에는 안전한 최솟값과 최댓값을 적용한다.
- 잘못된 저장값이 발견되면 해당 항목만 기본값으로 복구한다.
- 숫자 항목의 마지막에는 현재 모양 값으로 표시되는 토큰 기록 시간을 `Visible token history: N min N sec` 형식으로 표시한다. 값 확정과 기본값 복원 시 문구도 함께 갱신한다.

### 9.5 Overlay Position 그룹

- 오른쪽에는 `Overlay Position` 안내 문구만 표시한다.
- 이 그룹의 선택 상태가 사용량 오버레이의 외곽선과 드래그 모드를 제어한다.

## 10. 사용량 오버레이 데이터와 V1 호환 기준

- ManaBar는 5시간 세션의 남은 비율을 표시한다.
- HpBar는 주간 한도의 남은 비율을 표시한다.
- 각 게이지 중앙에는 남은 비율을 백분율 텍스트로 표시한다.
- 각 Refresh 게이지는 현재 한도 창에서 초기화까지 남은 시간 비율을 표시한다.
- 토큰 그래프는 Codex의 `.codex\sessions`와 `.codex\archived_sessions` JSONL 기록을 읽는다.
- 토큰 그래프의 시간 해상도는 15초다. 버킷 수는 사용량 오버레이 폭, 게이지 영역 폭, 막대 폭과 간격으로 실제 그래프 영역에 들어가는 수를 매 폴링마다 계산한다.
- 기본 모양에서는 15초 버킷 89개, 총 22분 15초의 실제 로그를 읽어 그래프 전체 폭을 채운다.
- 그래프 오른쪽이 최신 구간이다.
- 토큰 막대 높이는 화면 내 최대 버킷을 전체 높이로 두고 `10K` 토큰 knee의 `log(1 + value / 10K) / log(1 + maximum / 10K)` 완화 로그 비율을 사용한다.
- 0 토큰은 `0px`, 양의 토큰은 최소 `1px`, 화면 내 최대값 이상은 그래프 전체 높이로 제한한다.
- 토큰 막대 색상은 기존처럼 실제 토큰 수 `10K~100K` 구간을 선형 보간한다.
- 5분 간격을 구분하는 세로 점선을 유지한다.
- OpenAI 서비스 상태가 정상이면 상태 수직바를 숨기고, 장애 또는 상태 확인 실패일 때만 표시한다.
- 장애 상태 수직바가 표시되는 동안 사용량 오버레이 위에 마우스를 200ms 머무르면 영문 툴팁을 표시한다. 첫 줄은 `OpenAI service issue: {상태 설명}` 형식이며, 상태 설명은 OpenAI 상태 API가 반환한 실제 설명을 사용한다. 설명이 비어 있으면 `OpenAI service issue detected.`를 표시한다. 두 번째 줄에는 실제 장애 구성요소 이름만 `ChatGPT, Codex` 형식으로 표시하며, 정상과 FedRAMP 전용 항목은 제외한다. 목록이 없으면 두 번째 줄을 생략한다. 고정 360px 제한 대신 현재 가상 데스크톱 전체 폭을 사용해 실제 툴팁의 행바꿈을 활성화한다.
- 상태가 정상 또는 상태 확인 실패(알 수 없음)일 때는 툴팁을 표시하지 않는다. 툴팁은 오버레이의 Alt+Tab 제외와 비활성 창 동작을 바꾸지 않으며, 마우스 이탈·위치 변경 드래그·오버레이 숨김·재생성·종료 시 즉시 사라진다.

## 11. 설정과 로컬 데이터

- 사용자 설정은 `%LOCALAPPDATA%\settings.json`에 버전이 있는 JSON으로 저장한다.
- 현재 스키마 버전은 `3`이며, 사용량 오버레이 크기는 `overlayWidth`, `overlayHeight` 키로 저장한다.
- 스키마 `2`의 기존 크기 키는 값 손실 없이 자동 마이그레이션하고 새 저장에는 쓰지 않는다.
- 제한된 순환 진단 로그는 `%LOCALAPPDATA%\Logs`에 저장한다.
- `%LOCALAPPDATA%\CodexHp` 밖에 불필요한 파일을 만들지 않는다.
- 인증 토큰은 설정 파일과 진단 로그에 기록하지 않는다.
- 설정 파일이 없으면 문서에 정의된 기본값으로 생성한다.
- 설정 파일의 일부 값이 없으면 해당 값만 기본값으로 보충한다.
- 설정 파일이 손상되면 복구 가능한 범위에서 기본값으로 복원하고 사용자가 알 수 있는 상태를 남긴다.
- 멀티 모니터 위치 복원을 위해 모니터 식별 정보와 모니터 전체 영역 기준 물리 좌표를 저장한다.

## 12. 오류 처리 원칙

- 인증 없음, 네트워크 실패, 사용량 응답 변경, 로컬 로그 없음, OpenAI 상태 조회 실패를 서로 구분한다.
- 일시적 실패는 트레이 프로세스를 종료시키지 않는다.
- 사용할 수 있는 데이터는 일부 공급자가 실패해도 계속 표시한다.
- 마지막 성공값을 표시할 경우 현재 값이 아님을 시각적으로 구분한다.
- 로그에는 토큰, 인증 헤더, 계정 식별자를 기록하지 않는다.

## 13. 검증 기준

핵심 기능 마일스톤의 검증 기준은 다음과 같다.

- ChatGPT 앱과 Codex가 정상 로그인된 환경에서는 CodexHp용 로그인이나 설정 없이 한도와 그래프가 표시되어야 한다.
- 인증 캐시가 나중에 생성되는 경우 프로그램 재시작 없이 자동으로 정상 상태로 전환되어야 한다.
- 시작 프로그램 등록의 기본 활성화와 옵션 변경을 검증해야 한다.
