# Service Issue Tooltip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the OpenAI service-status description and affected component names in a non-activating tooltip after the pointer rests over the Usage Overlay while the service-issue stripe is active.

**Architecture:** Preserve the status API description and non-operational component names alongside the existing `ServiceHealthState`, then reduce them into optional two-line tooltip text on `UsageOverlayState`. `WpfOverlaySurface` owns one native Win32 tooltip control targeted at its overlay HWND; its enabled state and text follow the reduced state. The native control supplies the 200ms hover delay, uses the virtual-desktop width to activate hard line breaks without the prior 360px fixed limit, and closes automatically on pointer exit, while the surface explicitly disables it during lifecycle changes.

**Tech Stack:** .NET 10, WPF composition surface, Win32 common-controls tooltip (`tooltips_class32`), xUnit.

## Global Constraints

- Target Windows 11 build 22000 or newer only.
- Keep the app a single self-contained `CodexHp.exe`; add no third-party package or helper process.
- All user-visible text is English.
- The Usage Overlay remains hidden from Alt+Tab and must not activate when a tooltip appears.
- Use physical pixel coordinates for the Usage Overlay.
- A tooltip is enabled only for the logical `Issue` state, not because a particular customizable color happens to be orange.
- The default hover delay is 200 ms; no setting is added.
